# SKL 坐标助手

一个面向 `https://skl.hdu.edu.cn/` 的 Chrome Manifest V3 扩展。它管理预登记的 WGS-84（EPSG:4326）坐标，在目标页面调用 Web Geolocation API 时返回当前选中的坐标。切换位置后，页面“当前位置”和后续签到验证请求的坐标会立即使用新位置，无需刷新；填写四位签到码也会自动启用对应的 `code` 参数改写。

当前版本不接管登录，也不处理或绕过阿里云验证码。

## 本地安装

1. 打开 `chrome://extensions/`。
2. 开启右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择本仓库根目录。
5. 点击扩展图标，登记 WGS-84 纬度、经度并启用；如需改写签到码，填写四位数字即可自动保存并启用。
6. 初次安装后打开或刷新一次 SKL 签到页面，以加载扩展脚本。此后切换位置不需要刷新。

进入 `#/sign/in` 后，配置窗口会自动显示在页面右上方。拖动绿色标题栏可在当前页面移动窗口；重新进入签到页面时会自动回到右上角。点击右上角按钮可收缩为仅显示当前地点与签到码改写状态的简略模式，按钮所在的右上角在形状变化期间保持不动，收缩状态会自动记忆。扩展图标中的 Popup 仍作为备用入口保留。

填写四位签到码后可点击“使用此签到码签到”。扩展会按照原页面数字键盘的触摸事件输入签到码，第四位输入后由原页面继续执行定位检查、阿里云验证码和签到结果处理；扩展不会绕过这些流程。

## 开发

项目没有运行时第三方依赖，可直接加载源码目录。Node.js 仅用于静态检查和测试：

```bash
npm run verify
```

## 工作方式

- `src/main-world.js` 在页面脚本运行前安装 Geolocation 适配层，并拦截 `fetch` 与 `XMLHttpRequest`。
- 请求改写仅作用于 `/api/ali-nvc/captcha-verify` URL 中已经存在的 `code` 和经纬度参数；坐标改写在启用有效位置时生效。
- `src/content.js` 从 `chrome.storage.local` 读取设置、桥接到页面主执行环境，并让签到页“当前位置”实时显示有效经纬度与登记的地点名称。
- `src/panel.js` 在签到页面创建与站点样式隔离的浮动配置窗口，并负责拖动、收缩和状态记忆。
- `src/background.js` 仅在用户点击“导出”后，将配置下载为 `skl-plugin-config.json`。
- Popup 可以手动导出或导入配置文件；导入不会触发自动导出。
- `popup/` 提供位置的新增、编辑、删除、切换和启停界面。
- 未启用或没有有效坐标时，调用会回退到浏览器原生定位。
- 页面脚本注入范围仅限 `https://skl.hdu.edu.cn/*`。

## 数据与使用边界

坐标保存在本机 Chrome 扩展存储；只有点击“导出”后，配置文件才会写入浏览器的默认下载位置。扩展不会主动上传到其他服务。签到码仅保存在扩展存储中，不写入导出的配置文件。请只在你有权使用的账户、地点和测试场景中使用。
